# QA Issue Register

This file tracks product/software issues found during CertMocks testing and code review.
Question-content quality is intentionally outside this register.

## Status legend

- **Open** — confirmed issue, not fixed yet
- **Fixed** — code change completed
- **Verified** — fix has been manually/regression tested
- **Monitor** — fixed, but worth watching for recurrence

| QA-014 | Review unanswered | **Review could loop after partially answering the review queue.** Reproduction: skip all 10 questions, start **Review Unanswered**, answer/check Q1, Q3, Q5, Q7 and Q9 while skipping the even-numbered questions. After Q9, **Next Unanswered** could be pressed repeatedly and the review did not reach a clear end/submit state. Expected: review should make one forward pass through the captured unanswered queue and, after its final item, show the final submission confirmation; questions deliberately left unanswered remain reported as unanswered. | Fixed | Review now uses a stable, forward-only queue captured when review starts. | QA-015 | Exam launch / attempt state | **A new exam launched from the Dashboard could resume an old in-progress attempt and show a previously selected answer on Q1.** Reproduction: leave a domain mock in progress with at least one checked answer, return to Dashboard, then press **Start Exam**. The Dashboard used `/exams/{id}` (resume semantics) while the Mock Exams page used `?fresh=1` (fresh-attempt semantics), so identical-looking start actions behaved differently. Expected: intentional start/continue actions create a clean attempt with no preselected answers; direct refresh/resume keeps the current attempt. | Fixed | Both Dashboard and Mock Exams now use the shared `freshExamHref()` launch path. Fresh-launch links disable Next.js prefetch so merely viewing a page cannot trigger the server-side fresh-attempt transition. Direct `/exams/{id}` remains the resume path. Fixed through `d6eb00142e3db1acede1a8438aff61efe176a5d7`. |

| QA-016 | Dashboard statistics | **“Questions Done” was ambiguous and could be mistaken for questions answered correctly.** The value actually represented unique questions attempted at least once, regardless of whether the answer was correct or incorrect. Expected: label the metric clearly as **Questions Attempted** and provide a separate **Questions Mastered** metric for unique questions answered correctly at least once. | Fixed | Dashboard now shows **Questions Attempted** for unique attempted questions and **Questions Mastered** for unique questions with at least one correct completed answer. Both labels include a mobile-friendly info control explaining exactly what is counted. |

| QA-017 | Progress consistency | **Dashboard and Quiz progress used different definitions of an answered question.** The Dashboard counted only selected answers from completed attempts, while Quizzes counted any persisted selection, including draft or abandoned rows. This could show values such as **38 Questions Attempted** on Dashboard but **39 of 60 answered** on Quizzes. The Dashboard mastery metric also meant “ever correct,” while Quiz revisit logic uses the latest verdict. Expected: progress should be based on checked/scored answers, draft selections should not count, and the latest verdict should determine current mastery. | Fixed | Dashboard and Quiz progress now both ignore rows without a correctness verdict. Dashboard **Questions Attempted** counts unique checked/scored questions, and **Questions Mastered** counts unique questions whose latest checked verdict is correct. Regression coverage was added for latest-verdict behavior. |

| QA-018 | Practice / Quiz feedback | **Single-choice answers stopped revealing the explanation immediately.** In Practice/Quiz, tapping an option only stored a temporary selection and required a separate **Submit Answer** button located below the answer list. On mobile, the persistent bottom bar could make that extra action easy to miss, so the learner could press **Next** and move on without ever seeing the verdict, Key Idea or explanation. Expected: a single-choice tap commits the answer and immediately reveals feedback; multi-select questions remain editable until the required number of choices is selected and then use **Check Answer**. | Fixed | Single-choice answers now commit immediately and auto-scroll to feedback. Multi-select questions retain an explicit **Check Answer**, and the persistent top/bottom action changes to **Check Answer** whenever a multi-select choice is pending so **Next/Finish** cannot silently discard it. |

| QA-019 | Free tier / Subscription | **The Free plan had no clear usable action, and treating it like a normal ₹0 subscription would have been unsafe.** The product decision is that every registered free user automatically receives one free 10-question session in each quiz, plus the other baseline free features. The Subscription page showed a Free card with the same selector treatment as paid plans, but there was no clear **Continue Free** action. More importantly, sending that ₹0 plan through checkout would create an active all-certification subscription, which could unintentionally unlock premium content. Expected: the Free tier requires no activation/payment, should clearly show that it is the current baseline plan for non-subscribers, and should take the user directly to free content without creating a subscription. | Fixed | The Free card now shows **Current plan** for users without a paid subscription, explains that no activation is required, and provides **Continue with Free** to the Quizzes page. Its feature list explicitly states **1 free 10-question session in each quiz**. Checkout now rejects attempts to activate the baseline Free plan as a subscription, preventing accidental premium entitlement. A regression test covers free-plan classification and the displayed quiz allowance. |

| QA-020 | Subscription plan selection | **Paid plans did not show an obvious action button on mobile.** Monthly, Quarterly and Annual cards relied on tapping the entire card and showed only a thin radio-style bar at the bottom. For a new user this looked like there was no way to choose a paid plan. Expected: every paid plan should have a clear, tappable CTA and the purchase section should clearly identify the selected plan. | Fixed | Each paid plan now shows an explicit **Choose Monthly / Choose Quarterly / Choose Annual** button. The selected card changes the CTA to **[Plan] selected**, owned plans show **Already owned**, and the checkout section names the selected plan. Card-tap selection remains available as a secondary shortcut. |

| QA-021 | Free tier / Dashboard | **Free users were repeatedly sent to “Unlock” from the Dashboard even though the Free tier is automatic and does not need to be purchased.** The Dashboard treated “no paid subscription” as if the account had no plan at all, while locked mock-exam cards used a generic **Unlock** CTA. This made users think they had to activate or buy the ₹0 Free plan again each time. Expected: free access should persist automatically, free quiz entitlement should be visible on the Dashboard, and premium mock exams should clearly ask for an upgrade rather than another Free-plan activation. | Fixed | The Dashboard now shows **Free plan active** with **Continue Free Quizzes** and **View Paid Plans** actions. Locked mock-exam cards say **Upgrade for Mock Exams**. The Mock Exams page uses the same wording. Legacy ₹0 Free subscription rows are explicitly ignored by premium-access checks so they cannot unlock paid content. The obsolete **1 mini mock exam** claim was removed from the baseline Free feature list; free entitlement is the agreed one 10-question session in each quiz plus basic stats. Regression tests cover baseline-vs-premium plan classification. |

| QA-022 | Deployment workflow | **Every Git commit triggered a Vercel deployment, creating unnecessary builds and making it easy to test an intermediate commit instead of the completed fix.** Expected: development commits should accumulate without deploying; only an intentionally marked release commit should trigger Vercel. | Fixed | `vercel.json` now uses an Ignored Build Step based on the commit message. Commits are skipped by default; a commit containing **[deploy]** proceeds with a build. This lets related code, tests and QA documentation be committed first, then deployed together with one final release commit. |

| QA-023 | Free quiz entitlement | **The free-user flow could loop between Dashboard → Quizzes → Subscription → Free plan → Quizzes after the user's free 10-question session was already consumed.** Dashboard and the Free plan always advertised a continue action without checking whether any free quiz allowance remained. A free user with 10/60 answered therefore saw **Subscribe to continue**, then **Continue with Free**, which returned to the same locked quiz. Expected: once all currently available free quiz sessions are used, the UI should say so and offer paid plans rather than another free continuation. | Fixed | Dashboard and Subscription now derive whether any published quiz still has a free sitting available. If none remain, Dashboard shows **Free quiz allowance used** and Subscription disables the Free CTA as **Free quiz allowance used**. Locked quiz cards explicitly say the free 10-question session is complete. The restart API now also blocks free users from resetting a locked/mastered quiz to regain another free session. Regression tests cover free-session availability. |

| QA-024 | Free quiz entitlement / resume | **Quiz progress and the free limit were inferred from any answer to the same question, regardless of whether it came from that quiz, Practice, or a Mock Exam. Starting a quiz also created a new attempt instead of resuming an unfinished sitting.** This could consume a free allowance incorrectly, create duplicate in-progress attempts, and let a user obtain more than the intended one free sitting. Expected: quiz progress belongs only to QUIZ attempts carrying that exact quizKey; a free account gets one sitting per quiz; an unfinished sitting is always resumed; completing or abandoning it consumes that quiz's free allowance. | Fixed | Quiz history is now isolated by mode + stored quizKey. Free entitlement is attempt-based rather than answer-count-based. An existing in-progress sitting is returned by the start API instead of creating another. Free entitlement deliberately ignores QuizReset, while paid reset history remains supported. Pure regression tests cover metadata parsing and free sitting state. |
| QA-025 | Quiz / Practice answer durability | **Quiz and Practice feedback was local-only until Finish. Closing or reloading could lose checked answers, and an unfinished free quiz could be started again because the server had no durable checked progress.** Expected: Check Answer is the persistence boundary; feedback appears only after the checked answer is safely stored, and reload restores checked answers/explanations. | Fixed | Added an authenticated per-answer endpoint for QUIZ/PRACTICE. Checked answers are saved and locked before feedback is revealed. PracticeInterface resumes persisted checked answers, prevents navigation while a save is in flight, labels Quiz sessions correctly, and warns that finishing consumes a free quiz sitting. |
| QA-026 | Free/premium flow consistency | **Several surrounding screens disagreed with the entitlement model.** Free users could see a working Save button that always failed, Practice defaulted to 20 even though free sessions allow 10, Quiz/Practice results were shown as Passed/Failed, Dashboard exam score cards included Quiz/Practice attempts, Recent Results labelled quizzes as Practice Session, and changing paid plans could leave a coupon discount from the previously selected plan on screen. | Fixed | Bookmark control is visibly paid-only for users without certification access; Practice defaults to 10 questions; only EXAM attempts feed Exams Taken/Average/Best; recent quiz results use their quiz title; Quiz/Practice result pages no longer show mock-exam pass/fail semantics and return to the correct section; changing certification/paid plan clears the displayed coupon discount. |

| QA-027 | Quiz structure / retakes / review | **A 60-question domain was presented as one quiz pool, even though the intended product is six 10-question quizzes.** Paid users could receive another dynamically selected sitting rather than returning to a stable Quiz 1–6 set, and repeated attempts did not have a clean latest-review/history model. Expected: each domain exposes fixed per-user 10-question quiz slots; Quiz 1 is the free allowance, Quiz 2–6 require paid access, a quiz keeps its original questions across retakes, reviews remain available without creating attempts, and repeated attempts are kept under one quiz with latest score/best score/history. | Fixed | Quiz metadata now records quiz number, session kind and the assigned question IDs. The first assignment becomes that user's fixed set for the quiz; later retakes reuse it. Paid users unlock quizzes sequentially, can review the latest attempt, open attempt history, retry only incorrect questions, and use a mixed weak-question review after completing the domain. Free users receive one Quiz 1 attempt per domain and retain review access after completion. No database schema change is required. |

| QA-028 | Dashboard / Mock Exams separation | **Legacy 10-of-60 domain learning mocks were still displayed as Mock Exams, including on the Dashboard and dedicated Mock Exams page, even after the domain content moved to Quiz 1–6.** This made an untimed quiz-like activity look like a real exam and could also contaminate Exams Taken/Average/Best because those legacy attempts use EXAM mode. Expected: Dashboard is a progress summary only; the Mock Exams page lists only timed full-pool mock exams; legacy sampled domain mocks are excluded from mock-exam statistics. | Fixed | Removed the Dashboard Mock Exams content listing. Added a shared full-mock classifier: a real mock must be timed and serve its full linked pool. The Mock Exams page now filters out sampled domain learning mocks and uses full-exam wording, while Dashboard exam counts and Exams Taken/Average/Best use the same classification. Added regression tests for full vs sampled mocks. |

| QA-029 | Quiz / Practice review unanswered | **The Quiz/Practice Finish dialog showed unanswered counts but offered only Continue or See Results, so learners could not enter the established unanswered-only review flow.** This risked reintroducing the same navigation problems covered by QA-005/QA-014 if review were added as ordinary sequential navigation. Expected: Review Unanswered captures a stable queue of only the questions unanswered when review starts; Previous/Next move only inside that queue; it never falls through to correct/incorrect questions or wraps after the final queued item; the final item returns to the finish confirmation. | Fixed | Added **Review N Unanswered** to the Quiz/Practice finish dialog. Review mode uses a captured forward-only unanswered queue, changes navigation to Previous/Next Unanswered, prevents navigator jumps to questions outside the captured queue, and shows Finish Review on the final queued question. Added regression tests for queue membership, order and no-wrap behavior, explicitly mirroring the protections from QA-005/QA-014. |

| QA-042 | Quiz / mistake-practice finish flow | **When every question in Retry Incorrect was already answered, pressing Finish still opened the generic “Finish Quiz?” confirmation with Back to Quiz / See Results.** This added an unnecessary step and made a mistake-practice session look like a full quiz. | Fixed | Finish now checks the unanswered count first. | QA-043 | Full-attempt count after mistake practice | **After finishing Retry Incorrect, “Full attempts” remained at 2 and appeared stuck.** Code review confirmed this is the intended data model: Retry Incorrect is an INCORRECT_RETRY learning session, not a numbered full Quiz attempt. | Fixed | The count logic remains intentionally unchanged: only STANDARD full quiz sessions increment Full attempts/history. | QA-046 | Individual quiz card density | **Inside an expanded domain, every Quiz 1–6 card remained fully expanded, making the page long and noisy even after domain-level collapse was added.** | Fixed | Each Quiz card is independently collapsible. | QA-047 | Sequential quiz unlock rule | **The prior rule allowed Quiz N+1 after Quiz N was fully answered even when some answers were still wrong.** | Fixed | Superseded by QA-048 and QA-051. ## End-of-cycle verification

Before release sign-off, re-test every row marked **Fixed** or **Monitor** and change it to **Verified** only after reproducing the expected behavior in the deployed application.

When a new software issue is found, add it here with the next QA number, reproduction summary, status, and fixing commit. Do not remove resolved issues; keeping them provides a regression history.
